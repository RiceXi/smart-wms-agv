## 运行环境与启动

### 获取源码

将交付的 ZIP 文件解压至具有写入权限的目录。通过 GitHub 获取时，选择包含成员三实现的分支或冻结版本。个人 Fork 使用 `dev/member-3` 分支。仓库压缩包中的工作目录为 `implementations/member-3/`。独立演示包的工作目录为包含 `package.json` 的目录。

### 环境要求

运行 `node -v` 检查 Node.js 版本。项目要求 24 或更高版本，已验证的环境为 Windows 11 和 Node.js v24.16.0。系统使用 Node.js 内置 HTTP 服务与 SQLite 模块，无第三方运行时依赖。

### 启动服务

在工作目录中执行以下命令。Windows 用户也可双击 `启动成员三系统.cmd`。脚本在首次启动时打开控制台，重复执行时复用已有实例。

```sh
node src/server.js
```

服务启动后，在本机浏览器访问 `http://127.0.0.1:3033`。依次选择“演示订单”和“启动”，可在地图中观察 AGV 执行出库任务。运行期间应保留服务进程。按 `Ctrl+C` 停止服务后，业务数据保存在 `runtime/wms-member3.db`，下次启动时从该文件恢复。

### 启动参数

浏览器打开 `http://127.0.0.1:3033`。健康检查：`http://127.0.0.1:3033/health`。使用 Ctrl+C 停止服务。支持 `PORT` 与 `WMS_DB` 环境变量；未设置时默认仅监听本机3033端口。

```powershell
$env:PORT = '3034'
npm start
```

数据库进程锁限制同一数据文件仅由一个服务实例写入。异常结束后的失效进程锁会在下次启动时检查并清理。

## 五分钟演示

1. 打开运行总览，检查预置的3个商品、9个库位、3批库存和10台AGV。可在仓储管理自行新增、编辑商品与库位，登记库存。
2. 点击“演示订单”创建并释放6张真实出库订单，或在“出库订单”创建多行订单，先预占再释放。重复释放幂等。
3. 点击“启动”，选择4×或8×。在实时地图选择车辆，查看未来路径、轨迹、任务、电量与状态。装卸在独立tick发生，卸货确认后才扣除库存。
4. 两台车空闲回岗时使用“预约竞争演示”，系统让真实在线车辆请求同一目标，检查原始冲突，再计算安全等待/绕行路线并显示在线运动。车辆按仿真步逐格移动。
5. 运行中封闭三个可选节点之一，查看新地图版本、受影响任务计划变化及map.routes.revalidated事件；无关路线和计划版本保持不变，再解封。也可通过 API 封闭其他未占用地面节点。
6. 注入急单，查看优先级10的任务在下一次可用车辆分配时优先进入队列；故障按钮中止车辆并触发任务恢复策略。
7. 所有车辆回岗后可使用“等待图注入”，显式注入三车环形等待图并观察真实车辆回退。自动化AC9另用三车目标格互占，基于实际规划失败形成等待环验证恢复。
8. 在事件页按车辆、任务、UTC时间、类型和关键词查询完整历史，每页40条；概览仅保留最近200事件。在运行分析查看吞吐趋势、任务耗时、利用率、取消数、冲突/死锁/恢复数与瓶颈格点Top8。暂停后载入历史回放，逐帧浏览实际保存的状态；回放时写入按钮锁定，返回实时后恢复。

## 数据、恢复与重置

默认数据库：`implementations/member-3/runtime/wms-member3.db`（相对于仓库根目录）。SQLite 原子事务同时保存完整业务/运行快照、完整事件日志和回放帧。预置场景是 `scenarios/default-scenario.json`，数据库和浏览器测试配置目录由个人 `.gitignore` 忽略。

退出并重新启动后，商品、库位、库存、订单、任务、车辆坐标/计划/载荷、地图历史和回放均保留。恢复后默认暂停，点击启动继续。事件使用固定场景epoch加tick的UTC仿真时间；现实性能测量使用真实高精度时钟，不参与业务调度。

重置前可停止服务备份整个数据库文件。界面“重置”需要确认，会清空当前场景业务与回放并按输入seed重新生成样例。它不会删除源码或测试证据。默认seed为20261119。

## 验证命令

```powershell
npm test
npm run clean-start-test
npm run benchmark
npm run conflict-scenarios
npm run browser-test
npm run soak
```

- `npm test`：Node内置测试，覆盖HTTP/SSE、输入校验、库存、订单和任务状态、单车路径、原子预约、同格/穿边、首尾相接、三车等待环、封路、充电、急单、三次确定性运行、回放、独立进程重启恢复、筛选和统计。
- `npm run clean-start-test`：仅复制package.json、源码、网页、场景到个人runtime隔离目录，从空库启动真实HTTP进程，验证无第三方依赖也能提供页面、资源、健康检查与默认数据；不会覆盖3033工作库。
- `npm run benchmark`：500个局部双车竞争微场景；10/30车各60任务、1800tick加速运行，记录真实耗时、成功计划P95与安全检查次数。报告写入 `evidence/benchmark-results.json`。`BENCH_TICKS`可缩短调试，正式证据使用默认1800。
- `npm run conflict-scenarios`：500个22×16完整仓图、10车真实Engine场景，变化seed、初始封路、订单数量/优先级/放货点，执行在线同格或相向边竞争、运行中封路/解封及部分急单。逐tick核查全部车辆，保留每场景定义和失败，分母固定500。采用内存SQLite、关闭回放的加速仿真，不代表任意拓扑或自然死锁概率。报告为`evidence/conflict-scenarios-2026-11-20.json`；`SCENARIO_COUNT`仅用于缩小调试，调试不替代正式500场景。
- `npm run browser-test`：启动隔离的内存服务与已有Edge无头浏览器，真实requestAnimationFrame计时、操作检查并截图，写入 `evidence/browser-results.json` 和PNG。浏览器配置全部在本实现runtime内。无需安装浏览器插件或测试包；其他Chromium路径可用 `EDGE_PATH` 指定。
- `npm run soak`：真实墙钟运行30分钟，10车每60ticks创建6任务，检查车辆安全和任务完成情况，写入 `evidence/soak-results.json`。此测试关闭回放且使用内存SQLite；不代表文件数据库增长或浏览器长期帧率。可用 `SOAK_SECONDS` 缩短调试，缩短结果不能写成30分钟测试通过。

## 模块与接口

- `src/engine.js`：WMS状态、调度评分、tick仿真、充电、故障、死锁、事件、查询与统计。
- `src/planner.js`：带等待动作的时空A*、格点/有向边原子预约、超时清理。
- `src/map-engine.js`：网格、节点、边、路径连续性与障碍校验。
- `src/db.js`：SQLite事务、运行快照、事件、回放、进程锁。
- `src/server.js`：本地HTTP、资源接口、命令、JSON-RPC、SSE、指标。
- `public/`：零构建步骤中文控制台与Canvas地图。
- `scenarios/`、`tests/`、`scripts/`：样例、回归测试、性能与浏览器验证。

完整接口与状态解释见 `API.md`；调度与一致性设计见 `DESIGN.md`。

## 限制

这是单进程个人实验版。没有微服务/Kafka/Redis/K8s，也没有宣称整合版推荐技术全部实现。保守的路径末端占位有助于安全，但会降低密集窄巷吞吐；时空搜索有界，不保证任意动态地图都找到全局最优解，超时会有可解释失败。单格仍最多一台车，即使站点标注的逻辑容量更大。

执行中故障把原任务及未完成订单记为失败，释放预占，再创建替代订单/任务；原终态不会复活。实物载荷返库属于仿真抽象，不涵盖真实硬件救援。

性能证据只支持其指定场景。加速1800tick、1800秒内存墙钟实验、300秒文件数据库浏览器实验分别记录；尚无30分钟浏览器/磁盘结果。新增500场景为受控完整仓库样本，也不等于任意拓扑保证。事件/回放完整保留，长期运行数据库增长，尚未提供压缩归档；事件查询仍全量读取后筛选，超大日志会增加查询成本。个人版本按[交付说明](DELIVERY.md)进入负责人冻结与跨 Fork PR 流程。
