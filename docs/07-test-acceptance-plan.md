# 测试与验收计划

## 1. 测试策略

测试优先证明调度和状态一致性，再验证视觉表现。每次 PR 运行受影响模块的快速测试；里程碑集成运行全量回归；发布前运行固定演示、30 台 soak test 和干净环境启动。

## 2. 质量等级

| 等级 | 范围 | 发布要求 |
| --- | --- | --- |
| P0 | 订单闭环、路径正确、无冲突、无永久死锁、实时地图、持久化 | 必须全部通过 |
| P1 | Kafka、Redis、网关、双 dispatch、观测、Compose/kind/Ansible | 必须全部通过或有无争议的明确限制 |
| P2 | 搜索、离线分析、对象存储、Serverless、3D | 可延期，但不得伪造 |

## 3. 功能验收

### T01 WMS 主数据

前置：空数据库。

步骤：创建 SKU、库位和初始库存；重复编码；创建负库存；更新位置。

预期：合法数据保存成功；重复编码和负库存被拒绝；查询结果与数据库一致。

### T02 出库订单与任务

前置：存在足够库存。

步骤：创建出库订单；释放订单；查询订单和任务。

预期：订单只释放一次；每个明细生成一个任务；重复释放不重复扣库存；订单和任务状态可互相追溯。

### T03 单 AGV 路径

前置：地图无其他车辆。

步骤：从固定起点规划到目标点；推进 tick 到结束。

预期：路径连续、每次只移动一格或等待；目标点正确；完成 tick 与路径长度一致。

### T04 首尾相接

前置：同一路径上两台 AGV 可连续移动。

步骤：AGV A 在 tick `t` 通过格点，AGV B 在 tick `t+1` 通过。

预期：允许预约，不发生重叠。

### T05 顶点冲突

前置：两个任务争用同一格点同一 tick。

步骤：同时请求预约。

预期：最多一个成功；另一个等待、绕行或返回 `PATH_CONFLICT`；不能部分占用。

### T06 边冲突

前置：两台 AGV 位于相邻格点。

步骤：请求同一 tick 相向通过。

预期：系统禁止穿边，至少一台等待或重规划。

### T07 死锁恢复

前置：三车环形等待场景。

步骤：推进仿真并触发等待图检测。

预期：识别完整环；选择最低优先级车辆回退；释放预约；最终所有任务继续或按规则失败。

### T08 临时封路

前置：AGV 已有经过目标格的路径。

步骤：封路并增加地图版本。

预期：受影响路径重规划；未受影响路径保留；旧路径版本失效；无车辆驶入封路格。

### T09 充电

前置：车辆电量低于阈值。

步骤：完成当前任务后进入充电队列。

预期：充电位容量不被突破；车辆充满后回到可用状态。

### T10 订单完成与库存

前置：订单包含一条任务。

步骤：AGV 完成取放并发布完成事件。

预期：任务只完成一次；库存只扣一次；订单在所有明细完成后完成。

### T11 WebSocket 快照

前置：仿真运行中。

步骤：连接、断开、运行若干 tick、重新连接。

预期：重连取得新快照；前端车辆和任务与后端一致；重复消息不产生重复任务。

### T12 回放

前置：保存一段固定 seed 事件流。

步骤：暂停、单步、加速、回到起点回放。

预期：关键事件序列与原始运行一致；展示轨迹来自事件数据。

### T13 分析口径

前置：完成和取消若干任务。

步骤：查询吞吐、平均耗时、利用率和瓶颈 TopN。

预期：与事件统计结果一致；窗口、单位和分母明确。

### T14 重启恢复

前置：已有订单、任务和仿真快照。

步骤：重启 MySQL、Redis 和服务。

预期：业务数据不丢失；Redis 运行态从快照和数据库重建；未完成任务可以继续或进入明确失败状态。

## 4. 性能测试

### 调度

输入：30 台 AGV、100 个待指派任务、固定 24x24 地图。

记录：

- 指派延迟 P50、P95、P99。
- A* 搜索节点数。
- 冲突重试次数。
- 内存占用。
- 500 场景成功率和死锁次数。

通过：指派 P95 小于 200 ms；500 场景冲突消解成功率不低于 95%；30 分钟无永久卡死。

### 前端

输入：30 台 AGV、100 个任务、20 个告警、持续 10 分钟增量更新。

记录：

- 平均和最低 fps。
- 浏览器主线程长任务。
- WebSocket 消息大小和频率。
- 重连恢复时间。

通过：持续不低于 20 fps；重连 2 秒内恢复；无明显内存持续增长。

### 服务

记录 gateway、dispatch、sim 的 P95 延迟、错误率和资源占用。性能数据必须附机器规格、软件版本、JVM 参数和数据量。

## 5. 固定场景

| 场景 | 用途 | seed 和输入 |
| --- | --- | --- |
| `single-agv` | 闭环演示与回归 | 1 台 AGV、1 个订单 |
| `peak-30` | 规模、吞吐和前端性能 | 30 台 AGV、30 个以上任务 |
| `head-to-head` | 相向穿边 | 两台 AGV、单窄巷 |
| `cycle-deadlock` | 三车死锁恢复 | 三台 AGV、环形等待 |
| `roadblock` | 封路重规划 | 高峰场景加临时封路 |
| `low-battery` | 充电队列 | 多台低电量车、有限充电位 |
| `rush-order` | 急单插入 | 高优先级订单插入低优先级任务池 |

每个场景保存 map version、seed、初始实体、预期关键事件和指标基线。

## 6. 自动化层级

- 单元测试：状态机、评分、路径、预约、死锁、指标计算。
- 集成测试：MySQL、Redis、Kafka、服务接口。
- 契约测试：OpenAPI、事件 schema、WebSocket 消息。
- 端到端：登录、创建订单、启动仿真、查看完成、回放。
- 性能：调度批测、500 场景、30 分钟 soak、前端 fps。

## 8. 缺陷等级

| 等级 | 定义 | 示例 |
| --- | --- | --- |
| P0 | 演示阻断或数据明显错误 | 车辆重叠、任务卡死、库存重复扣减 |
| P1 | 核心功能错误但有绕行方式 | 单场景重连失败、指标小范围偏差 |
| P2 | 非核心功能或体验问题 | P2 检索不可用、图表样式错误 |
| P3 | 文案和低影响问题 | 标签不一致、非关键排序不稳定 |

发布前不得存在未说明的 P0/P1。
