# 个人开发契约

## 1. 目标

三名成员分别使用不同 AI 工具，独立完成同一个仓储 WMS 与 AGV 调度系统。三份实现的业务行为必须一致，技术栈和架构可以不同。

## 2. 工具与目录

| 成员 | AI 工具 | 分支 | 实现目录 | 报告 |
| --- | --- | --- | --- | --- |
| 成员一 | DeepSeek-V4.1-Flash | dev/member-1 | implementations/member-1/ | docs/report/member-1.md |
| 成员二 | MiniMax M3.1 Flash | dev/member-2 | implementations/member-2/ | docs/report/member-2.md |
| 成员三 | Gemini-4-Carbon | dev/member-3 | implementations/member-3/ | docs/report/member-3.md |

## 3. 必须满足

- 本地运行。
- 数据持久化。
- 遵守 `docs/data-schema.md`。
- 通过 `docs/acceptance.md` 中的核心用例。
- 提供独立运行说明。
- 提供个人 AI 使用记录。
- 提供个人需求分析、设计说明、测试结果和分析报告。

## 4. 实现目录最低交付

每个 `implementations/member-N/` 至少包含：

- 源码和依赖清单。
- `README.md`：版本、安装、启动、测试和数据位置。
- `ai-notes.md`：AI 使用过程、错误和人工修改。
- 测试或验收脚本。
- 固定演示场景或样例数据。

## 5. 技术栈

个人版本不强制统一，但必须说明：

- 语言和运行时版本。
- 依赖安装方式。
- 启动和测试命令。
- 数据文件或数据库位置。
- 实际支持的功能和限制。

## 6. 课程推荐技术

课程要求属于推荐技术范围。个人版本可以选择适合的实现路径；整合版必须对适用技术给出可运行证据。

| # | 推荐技术 | 项目适用方式 |
| --- | --- | --- |
| 1 | Spring Boot | 服务实现或整合版基础框架 |
| 2 | Spring Cloud | 网关、调用、配置与注册 |
| 3 | SOA / 微服务 | 按订单、任务、调度、仿真和展示拆分 |
| 4 | Docker / K8s | 容器化与单节点编排 |
| 5 | Redis | 状态、预约、优先级和幂等 |
| 6 | 分布式消息 | Kafka 承载订单、任务和 AGV 事件 |
| 7 | Zookeeper / Eureka | 选择 Eureka 做注册发现 |
| 8 | RESTful API | 业务接口与 OpenAPI |
| 9 | JSON-RPC over HTTP | 仿真与调度高频调用 |
| 10 | 负载均衡 | 网关分流调度实例 |
| 11 | Hadoop | 选择 HDFS + MapReduce，HBase 可选 |
| 12 | Elasticsearch | 任务、异常和 trace 检索 |
| 13 | Serverless / FaaS | 日报、轨迹压缩或快照函数 |
| 14 | Ansible | 演示环境配置管理 |
| 15 | CI/CD | 选择 GitHub Actions |
| 16 | SkyWalking | 跨服务链路追踪 |
| 17 | Prometheus + Grafana | 吞吐、冲突、死锁和利用率 |

每个技术项最终需能指出代码或配置、启动命令和可观察结果。只在架构图中出现不算完成。

## 7. 独立性

- 个人版本冻结前，不得查看或复制其他成员实现。
- 不得修改公共契约来适配个人实现。
- 不得由其他成员代替完成核心实现。
- 发现需求或契约歧义时，先报告项目负责人。
- 公共文档修改必须走独立 PR，不得混入个人实现提交。

## 8. 个人报告最低内容

- 需求分析。
- 方案和技术选型。
- 核心数据结构与模块设计。
- 关键提示词和 AI 迭代过程。
- AI 错误、幻觉和人工修改。
- 验收执行结果。
- 性能和规模。
- 限制、风险和反思。

## 9. 完成定义

一个个人版本只有同时满足以下条件才算完成：

- 能从干净环境按说明启动。
- 核心功能可操作。
- 冲突和死锁处理有效。
- 数据重启后不丢失。
- 验收用例有记录。
- 个人报告包含 AI 过程与人工修改分析。
- 个人版本已打冻结 tag。
