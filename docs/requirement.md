# 需求规格说明书：仓储 WMS 与 AGV 调度系统

## 1. 项目目标

开发一款可在本地独立运行的智能仓储系统，完成“出库订单 -> 拣选任务 -> AGV 指派 -> 路径规划 -> tick 仿真 -> 实时地图 -> 指标分析”的闭环。

三名成员基于本文档独立完成个人版本。技术栈可以不同，但业务状态、路径冲突规则、数据字段和验收行为必须一致。个人版本冻结后，小组选择一个基础版本完成整合优化版。

## 2. 用户角色

当前阶段为单机演示系统，不建设完整账号体系。用户可以：

- 维护商品、库位、库存和订单。
- 查看任务和 AGV 状态。
- 启动、暂停、单步或加速仿真。
- 注入故障、封路和急单。
- 查看任务、冲突、死锁、利用率和瓶颈巷道。

## 3. 系统范围

### 3.1 必须实现

- 单仓库、单地图和单组 AGV。
- WMS 主数据和出库订单。
- 任务池和任务状态机。
- AGV 指派与时空路径规划。
- tick 仿真和固定 seed 回放。
- 2D 地图实时展示。
- 冲突、死锁、封路和充电处理。
- 本地持久化和基本分析。

### 3.2 可在整合版增强

- Kafka、Redis、Eureka、微服务拆分。
- Docker、Kubernetes、Ansible、CI/CD。
- SkyWalking、Prometheus、Grafana。
- Elasticsearch、HDFS/MapReduce、Serverless。
- 3D 仓库视图。

个人实现可以采用单体或轻量架构，但必须覆盖功能需求；整合版负责完成课程推荐技术的完整组合。

## 4. 功能需求

### FR1 商品与库位

- 新增、编辑、查询和删除 SKU。
- SKU 编码全局唯一。
- 新增和编辑库位。
- 库位包含区域、坐标、类型和容量。
- 库位类型至少包括货架、拣选点、放货点、充电桩和封路格。

### FR2 库存

- 登记 SKU、库位、批次、数量和有效期。
- 库存数量不能小于 0。
- 出库订单释放时预占库存。
- 订单取消或失败时释放预占库存。
- 库存变化必须记录流水。

### FR3 订单

- 创建出库订单，至少包含单号、优先级、明细和状态。
- 订单状态至少包括草稿、已分配、已释放、已完成、已取消和失败。
- 订单释放后生成一个或多个拣选任务。
- 同一订单重复释放不能重复扣减库存。

### FR4 任务中心

- 查看任务列表和详情。
- 任务至少包含来源订单、取货点、放货点、优先级、状态和 AGV。
- 支持任务优先级调整。
- 支持待处理或已分配任务取消。
- 支持 AGV 故障后的任务重派。
- 任务状态必须符合数据契约。

### FR5 AGV 管理

- 显示 AGV 位置、状态、电量和当前任务。
- AGV 状态至少包括空闲、前往取货、装载、前往放货、卸载、充电、故障和离线。
- 电量低于阈值时进入充电队列。
- 充电桩容量不能被突破。
- 故障和离线 AGV 不能被指派新任务。

### FR6 地图与路径

- 地图使用二维离散网格。
- AGV 每 tick 只能停留或沿上下左右移动一格。
- 货架、封路格和越界格不可进入。
- 路径必须带时间戳，形成 `(x, y, t)` 序列。
- 路径需要同时预约格点和有向边，防止同格冲突和相向穿边。
- 地图变更后必须生成新版本。

### FR7 调度

- 按距离、负载、优先级、电量和可用状态选择 AGV。
- 支持等待动作。
- 支持高优先级任务优先预约。
- 支持临时封路后的局部重规划。
- 同一固定 seed 和输入必须得到相同关键事件序列。

### FR8 冲突与死锁

- 禁止两个 AGV 在同一 tick 占用同一格。
- 禁止两个 AGV 在同一 tick 相向穿过同一条边。
- 预约失败时返回明确冲突原因。
- 周期构建 AGV 等待图并检测环。
- 发现死锁后选择可回退车辆释放预约并重新规划。
- 回退次数或等待时间必须有上限。

### FR9 仿真

- 按 tick 推进 AGV 运动、装卸、电量和充电。
- 支持启动、暂停、继续、单步和重置。
- 支持 1x、4x 和 8x 速度。
- 支持故障、封路和急单事件注入。
- 事件和状态必须带 `tick`，支持固定场景回放。

### FR10 实时可视化

- 2D 地图显示货架、拣选点、放货点、充电桩和封路格。
- 显示 AGV 实时位置、状态、电量和当前任务。
- 显示路径、历史轨迹、任务连线和告警。
- 支持车辆选择和任务详情查看。
- 断线重连后必须重新取得完整快照。

### FR11 查询与筛选

- 按状态、优先级和 AGV 筛选任务。
- 按状态和单号筛选订单。
- 按 AGV、任务和时间窗口查询事件。
- 支持组合筛选条件。

### FR12 分析与统计

- 显示订单数、任务数和 AGV 数。
- 显示吞吐量、平均任务耗时和取消任务数。
- 按 AGV 统计利用率和完成任务数。
- 显示冲突次数、死锁次数和恢复次数。
- 显示瓶颈巷道 TopN。
- 至少提供一种图表或趋势视图。

### FR13 本地持久化

- 使用 JSON、SQLite、MySQL 或其他本地数据库保存业务数据。
- 程序重启后商品、库位、库存、订单和任务不能丢失。
- 数据文件或数据库位置必须在个人运行说明中注明。
- 运行态快照至少支持从持久化数据恢复。

### FR14 输入校验和错误提示

- 编码、名称、数量、日期和坐标必须校验。
- 数量、容量、电量和 tick 不能为非法值。
- 非法订单、任务、路径和状态流转必须拒绝。
- 用户必须看到可理解的错误原因。
- 删除或取消操作必须遵守状态和预约规则。

## 5. 非功能需求

- 可在主流桌面环境本地运行。
- 核心功能可离线使用。
- 代码结构清晰，关键调度逻辑有必要注释。
- 提供依赖、启动、测试、数据和重置说明。
- 固定场景可重复运行。
- 单 AGV 路径和冲突用例必须有自动化测试。
- 记录 AI 使用过程、错误和人工修改。

## 6. 性能与稳定性目标

| 指标 | 目标 |
| --- | --- |
| AGV 数量 | 个人版至少 10 台；整合版至少 30 台 |
| 前端帧率 | 2D 地图持续不低于 20 fps |
| 指派延迟 | 整合版 P95 小于 200 ms |
| 死锁 | 连续运行 30 分钟无永久卡死 |
| 冲突 | 无同格和相向穿边 |
| 冲突消解 | 500 场景成功率不低于 95% |

个人版无法达到整合版规模时，必须在报告中说明实测规模、机器环境和限制。

## 7. MVP 演示场景

1. 创建至少 3 个 SKU、5 个库位和初始库存。
2. 创建出库订单并释放任务。
3. 调度 AGV 从取货点到放货点。
4. 地图实时显示车辆和路径。
5. 注入两车冲突并展示等待、绕行或回退。
6. 注入临时封路并展示重规划。
7. 注入急单并展示优先级变化。
8. 展示任务完成、库存变化和统计结果。

## 8. 范围排除

- 真实 AGV、PLC、WCS 和仓储硬件接入。
- 多仓、多园区和真实企业权限体系。
- 云端同步、支付、邮件和短信。
- 真实地图和外部导航服务。
- 复杂 3D 物理引擎。
- 多语言和复杂主题系统。
