# 里程碑驱动开发计划

## 1. 开发原则

开发计划按可运行产物和退出条件推进。每个里程碑只有一个主目标；未达到退出条件时，不开启下一个里程碑的新功能。里程碑可以并行准备，但共享契约、核心状态和演示链路必须按依赖顺序冻结。

## 2. 里程碑总览

| 里程碑 | 目标 | 主责 | 退出条件 |
| --- | --- | --- | --- |
| M0 契约基线 | 冻结地图、任务、AGV、API 与事件契约 | 成员一 | 三人批准第一版契约；样例场景可解析；服务骨架可构建 |
| M1 单 AGV 闭环 | 一个出库订单由一台 AGV 完成 | 成员二 | WMS 创建订单后，任务、路径、tick 和前端状态一致；固定 seed 可重放 |
| M2 多 AGV 正确性 | 多车共用地图时不重格、不穿边、不永久卡死 | 成员二 | 10 台 AGV 固定场景和冲突场景通过；死锁检测与回退可重复 |
| M3 全栈集成 | 业务服务和前端通过统一入口完整联动 | 成员一 | 一条命令启动核心系统；演示剧本 A 不使用 mock 数据完成 |
| M4 规模与可靠性 | 达到 30 台 AGV 和持续运行目标 | 成员二 | 30 台高峰场景稳定；30 分钟 soak test 无永久死锁；关键指标可抓取 |
| M5 实时体验 | 地图实时展示、回放和断线恢复完成 | 成员三 | 30 台场景不低于 20 fps；重连后状态一致；1x 至 8x 加速可切换 |
| M6 技术能力补齐 | Kafka、部署、观测和 P1 技术链路可运行 | 成员一 | Kafka 主链路、Grafana、SkyWalking、kind 和 Ansible 在演示环境可用 |
| M7 发布封版 | 回归、演示、文档和发布包完成 | 成员三 | P0/P1 全通过；连续两次完整演示成功；干净环境按文档启动 |

## 3. M0 契约基线

### 目标

让三个人对同一张地图、同一条任务、同一台 AGV 和同一个 tick 有完全一致的理解，并建立能承载后续开发的最小仓库骨架。

### 工作内容

- 成员一：仓库结构、CI、网关与业务服务骨架、OpenAPI、错误码、事件 envelope。
- 成员二：地图节点与边、障碍、充电桩、AGV 状态、tick 定义、固定场景样例。
- 成员三：WebSocket 快照与增量、前端状态模型、地图渲染接口和空状态页面。
- 三人共同：评审任务状态机、AGV 状态机、事件字段和错误处理。

### 退出条件

- 所有服务暴露健康检查，`main` 可构建。
- OpenAPI 和事件 schema 能通过 lint。
- 样例地图可以被后端、前端和测试夹具读取。
- 三人不再对下列字段存在未决分歧：坐标、tick、状态枚举、优先级、幂等键。
- 契约冻结后使用 ADR 管理变更。

## 4. M1 单 AGV 闭环

### 目标

证明系统不是界面演示，而是真实完成“订单 -> 任务 -> 路径 -> 仿真 -> 完成”的可运行闭环。

### 必要能力

- WMS 维护最少量商品、库位、库存和出库订单。
- 出库订单生成拣选任务，任务可指派、运行和完成。
- 单 AGV 使用静态或时空 A* 完成取货、运载和放货。
- sim 按固定 tick 推进，输出 AGV 位置、任务阶段和电量。
- push 发送快照，web 显示任务、车辆和目标路径。
- 订单、任务、AGV 和路径状态可通过查询接口核对。

### 退出条件

- 使用固定 seed 创建同一订单，连续运行三次得到相同关键事件序列。
- 任务完成时 AGV 位于正确放货点，库存和订单状态一致。
- 服务重启后主数据和任务快照仍在。
- 非法任务状态流转被拒绝并返回稳定错误码。

## 5. M2 多 AGV 正确性

### 目标

在多车环境中证明路径、预约和冲突处理正确。该里程碑优先于视觉优化和额外技术接入。

### 必要能力

- 时空 A* 状态 `(x, y, t)`，动作包含等待。
- 顶点预约 `(cell, tick)` 和边预约 `(from, to, tick)`。
- 按优先级预约，支持等待、绕行、TTL 释放和重规划。
- 等待图、死锁环检测、最低优先级回退和重规划。
- AGV 故障、临时封路、充电阈值的最小处理。

### 退出条件

- 10 台 AGV 连续运行 10 分钟无重格和相向穿边。
- 窄巷双向、三车等待环、临时封路三个固定场景可复现并恢复。
- 同一 seed 的多车事件序列可重复。
- 调度内核可在无前端条件下独立测试。

## 6. M3 全栈集成

### 目标

把三条个人分支合成一条可启动、可操作、可诊断的完整链路。

### 必要能力

- gateway、auth、wms、task、dispatch、sim、push、analytics 接入统一入口。
- MySQL 保存主数据和任务快照；Redis 保存 AGV 状态、预约和幂等键。
- Kafka 接口已定义；若正式消息链路尚未稳定，本地适配器必须保持相同事件语义。
- 统一 request ID、结构化日志、健康检查和基础指标。
- 一条启动脚本、一套演示数据、一个固定剧本。

### 退出条件

- 从干净环境执行启动脚本后完成剧本 A。
- 关闭任一非核心服务时，网关和健康检查返回可诊断错误。
- 前端不使用 mock 数据完成订单创建、仿真和完成。
- 重启 MySQL 后业务数据不丢失，Redis 丢失后可重建运行态。

## 7. M4 规模与可靠性

### 目标

达到可量化的多车规模，并证明长时间运行不会因冲突或死锁永久停止。

### 必要能力

- 30 台 AGV、30 个以上任务的高峰场景。
- 任务优先级、急单插入、任务抢占或重派。
- 充电队列、充电桩容量和回岗。
- 500 场景随机压测入口，支持快速 smoke 和完整批测。
- Prometheus 指标：吞吐、指派延迟、冲突次数、死锁次数、AGV 利用率。

### 退出条件

- 500 场景中冲突消解成功率不低于 95%。
- 30 分钟 soak test 无永久卡死，所有死锁环都有恢复事件。
- 任务指派服务端 P95 小于 200 ms。
- 性能报告包含机器规格、JVM 参数、数据规模、seed 和测量方法。

## 8. M5 实时体验

### 目标

把后端的正确状态转化为稳定、可理解、可回放的实时地图。

### 必要能力

- WebSocket 快照、增量、告警和断线重连。
- 前端只对允许插值的字段做平滑，任务和 AGV 的最终状态以快照为准。
- 车辆位置、轨迹、任务连线、封路、拥堵热力和告警面板。
- 暂停、单步、1x/4x/8x、轨迹回放和固定 seed 重放。
- 30 台场景的前端性能采样。

### 退出条件

- 目标测试机 2D Canvas 持续不低于 20 fps。
- 断网 5 秒后恢复，2 秒内取得一致快照，无车辆瞬移或重复任务。
- 暂停、单步和加速不会改变后端事实时间。
- 回放结果与原始关键事件一致。

## 9. M6 技术能力补齐

### 目标

补齐课程和作品要求中的部署、消息、可观测与离线分析能力，不让扩展技术破坏 P0 核心闭环。

### 必要能力

- Kafka 正式消息链路和事件去重。
- dispatch 双实例、网关分流与幂等验证。
- Prometheus、Grafana、SkyWalking。
- Docker Compose、kind 单节点、Ansible。
- 按优先级实现 Elasticsearch、HDFS/MapReduce、MinIO、Serverless。

### 退出条件

- 禁用任一 dispatch 实例后，请求仍能完成。
- Grafana 包含吞吐、冲突、死锁和利用率面板。
- SkyWalking 能看到急单插入的跨服务链路。
- 从空环境按部署文档启动演示环境。
- P2 功能不可用时明确标记，不由前端伪造结果。

## 10. M7 发布封版

### 目标

把系统整理为可复现、可演示、可维护的交付包。

### 工作内容

- 全量 P0/P1 回归。
- 演示视频脚本、现场数据和答辩材料。
- 一键启动、重置和场景导入。
- API、架构、部署、测试和 AI 过程文档归档。
- 创建发布标签和封版说明。

### 退出条件

- 连续两次完整演示成功。
- 干净环境按 README 启动成功。
- 已知缺陷有等级、影响、规避方式和负责人。
- 所有代码目录有运行说明，所有服务有健康检查。
- 个人 AI 过程记录可追溯到关键功能与修复。

## 11. 关键依赖

```text
地图/状态/事件契约
  -> tick 与单 AGV
  -> 顶点和边预约
  -> 多 AGV 冲突与死锁
  -> 30 台规模
  -> WebSocket 与 20 fps
  -> 回放与演示
  -> 发布封版
```

WMS 和前端可以在契约冻结后并行开发。调度正确性未达到 M2 退出条件前，不进入大规模视觉优化。

## 12. 合并门禁

- 后端模块：编译、单测和模块集成测试通过。
- 调度模块：固定场景、冲突场景和随机 seed 回归通过。
- 前端模块：类型检查、单测和关键页面 Playwright 通过。
- 契约变更：OpenAPI/schema 校验通过，至少两名成员批准。
- 部署变更：从空目录执行启动脚本成功。
- 性能变更：附前后对比数据，不能用单次截图代替测量。

## 13. 范围调整规则

如果某个里程碑长期无法退出，优先缩小功能范围而不跳过正确性：

1. 保留 WMS、任务、调度、仿真、推送、前端和持久化闭环。
2. 延迟 Elasticsearch、HDFS、MinIO、Serverless、3D 和复杂展示。
3. 30 台规模无法稳定时，先保证 20 台无冲突，同时保留 30 台专项测试和真实限制说明。
4. 任何简化都不能伪造运行结果、性能指标或技术接入。
